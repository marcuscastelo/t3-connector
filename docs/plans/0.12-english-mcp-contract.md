# 0.12 plan: English public MCP contract

Status: proposal. No implementation, version bump, release or deploy is part of this document.

## 1. Decision and roles

- Decision (Marcus, 2026-10-05): `0.12` makes a deliberate breaking change to an English public MCP contract.
- There are **no** Portuguese aliases for tool names, arguments, fields or enum values.

## 3. Naming scheme

- Form: `t3_<resource>_<action>`, lower snake case.
- Names describe the operation. No `escrever` and no "write" category in names.
- The envelope stays: `environment`, `operationId`, `input`, plus `leaseId` only on Ponte. All fields, enum values and IDs are English.
- Do not change these, to avoid replay changes: action IDs, grant IDs, journal keys and their hash, `commandId`, and RPC routes and semantics.
- Keep cross-host discovery by title or ID (`t3_thread_find`) distinct from native content search (`t3_thread_search`).

## 5. Arguments, fields and aliases

- Every registered argument and every output key and enum value is already English.
- These legacy parameters are **rejected** by strict schemas: `ambiente`, `busca`, `limite`, `estado`, `incluirSemExecucao`, `correspondencia`, `maxCaracteres`, `incluirUltimaResposta`, `verificar`. Legacy state and match values are also rejected. They are not hidden MCP aliases. Do not add compatibility.
- Portuguese internal variables, relay fields and codes that are mapped at the boundary are not public aliases. Keep them unless one is exposed. No filesystem rename is needed.
- `statusRun` is already English. No change is required.
- Legacy config keys are also rejected. Their rejection messages are in Portuguese, in `src/config` and `src/escrita/config`. They are outside the MCP startup surface.
- CLI aliases (`ambientes`, `diagnostico`, `--ambiente`) are still accepted. They are outside the MCP scope and are not MCP aliases (appendix A).
- User-supplied data stays as given and is never translated: environment aliases, project titles, messages and provider names may be in Portuguese.

1. Create a separate branch from current `main`. Include the runtime fix (`8793347`) as a dependency, or integrate it separately first. Do not re-release `0.11`.
2. Add one public tool registry that maps action ID to tool name. Share it across:
   - read registrations;
   - Ponte tool generation and `LEITURAS` routing;
   - OAuth `writeToolName` and native registrations;
   - pending-request `nextAction.tool`;
   - tool references in errors and descriptions.

   Internal action IDs and journal IDs stay stable. Enforce name uniqueness and keep `t3_thread_find` and `t3_thread_search` semantically distinct.
3. Documentation:
   - README: remove the tool names that are still declared in Portuguese.
   - New ADR that supersedes ADR 0004 and closes the tool naming question.
   - Update `docs/oauth-session.md`, the environment and wait ADRs, `docs/releasing.md` and any affected examples.
   - CHANGELOG: a breaking entry with the full old → new table. Claude may also produce an optional machine-readable migration table.
   - Runtime release notes.
4. Tests and packaging: update test names and comments. Remove the stale "hidden aliases" claim from the package checker.

## 8. Gates

- Exact snapshot of tool names per profile and of the full catalog.
- No Portuguese tool names or legacy aliases in any live public catalog. Historical migration tables and negative rejection tests may name the removed tools. No old name dispatches to the backend.
- Strict schemas reject legacy parameters and enum values.
- No name collisions.
- Every `nextAction.tool` exists on the correct callable write surface.
- Recursive SDK schema check of keys, enum values and descriptions, including array items and `oneOf`/`anyOf`.
- OAuth: native and admin flags, scopes, and tool visibility under old grants.
- Lease reads on Ponte.
- Journal, dedupe and reconcile work under the new names, with the action keys unchanged and no duplicate send.
- Cursors refuse old queries.
- `npm test` and `npm run test:package` in CI on Node 22.13 and 24, on Linux and macOS. The read smoke derives environment aliases from the configuration in use rather than assuming fixed aliases or two environments.
- No live destructive tests.

## 9. Release and rollout (only with explicit authorization from Marcus)

- One breaking minor, `0.12.0`. Version fields, package lock, `VERSAO` and changelog must match exactly. Run the release gates, then publish the approved PR and tag through the existing CD.
- No patch backport of the new names to `0.11`.
- Approval for the artifact and its installation is separate.
- On install: restart the paired bridge and gate, and refresh the ChatGPT tool metadata. Preserve passkeys and the journal.
- OAuth consent, catalog and session capability do not change. There are no silent new grants. Evaluate the effects of the restart and document how clients reconnect.
- Rollback: reinstall the approved prior artifact and preserve existing state. Never replay uncertain operations.
- Nothing is published or deployed as part of this plan.
